# Pending combat adjudication boundary (in progress)

Baseline: 3c62f5c. This work continues in the separate proposal copy. No release sign-off.

A pending saving throw is an unresolved branch of game state. Later commands must not use the provisional branch, and an automatic turn sequence must stop before its next step. The implementation will use two shared pieces:

1. A campaign command guard at the existing authorization/round boundaries, with nested command reuse and a nonblocking per-campaign execution lease. Persisted pending decisions remain the authority; the lease is process-local, matching the server's existing single-process combat caches. It does not hold a pooled database connection through a command. Reads, speech, GM adjudication/correction and explicitly replacing the sole pending Concentration cast remain available.
2. Durable continuations containing only compiled, typed operation names and server-created data. When a damage save becomes pending, the concentration transaction records the continuation stack at that exact pause point. After adjudication, the GM resumes that saved work. Completed steps and costs are not replayed. A new pending decision updates the same work item. Completed work returns its recorded result on retry. A process interrupted while executing work must fail closed rather than blindly rerun a possibly committed step.

The first failing route probe showed turns and rests proceeding while a decision was pending. The shared new-command guard now passes that probe. This does NOT yet establish intra-command pausing. Next probes cover Burning at a turn's start, the following spell effects, persisted resumption, duplicate resume, and decision isolation. Attack/effect loops must be moved onto the same continuation owner before claiming the boundary is complete.

Rules are unchanged: the supplied SRD 5.2.1 Concentration and Legendary Resistance texts govern the decision. This is an execution boundary, not an invented game rule or a per-monster exception. Additional tables/columns remain in the one existing application database.
