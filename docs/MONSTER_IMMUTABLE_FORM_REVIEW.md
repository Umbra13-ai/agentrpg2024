# Immutable Form combat review

SRD 5.2.1 describes Immutable Form as preventing shape-shifting. The Polymorph description explicitly calls its transformation shape-shifting (p. 153). The unloaded trait should therefore block a target transformation before its Wisdom save. Code review shows the current Polymorph owner checks a legacy Shapechanger type but never reads this trait. The proposed route probe tests an ordinary imported control, an invented Immutable Form creature, and the same ability on a previously swept private reference fixture. The supplied reconstructed reference is read as input and remains outside the repository. This is one named ability test within the acceptance program. It does not establish a complete pass for the reference monster.

The probes have been prepared and are waiting for the current test batch. No failure or repair has been verified at this edit.

The first run exposed an invalid test column name. The fixture now uses the existing `intl` column. The corrected baseline (`immutable-form-before-2.log`) transformed both protected targets into a Wolf while the mutable control behaved as expected. The existing trait catalog now identifies Immutable Form and the shared Polymorph owner checks it before rolling a save. The Iron Golem and the invented protected target retained their form and HP. The mutable target still transformed. The trait registration and creature-type regression also passed (`immutable-form-after.log`).

A separate test imported the same supplied reconstruction and used the GM damage route on a wounded target. Forty fire healed forty HP, poison immunity did not heal, cold reduced HP, and absorption stopped at maximum HP. It passed before and after this trait fix. Both tests exercise named traits on this one reference monster. Its remaining traits, actions, and other stat-block mechanics still require the acceptance review.
