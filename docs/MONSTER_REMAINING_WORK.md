## Bracketed GM notes in logged results (audit, done; storage boundary fixed)

The monster_action result used to be stored whole in the shared action log, and some results carry a bracketed GM note

  shared log; it goes to the notices.

- Remaining delivery gaps: GM notes are delivered as notices only; if the notices table write fails they are held in memory and logged

## Concentration lifecycle boundaries (monster_concentration_2024.go)

- A concentrating monster's Constitution save is rolled WITHOUT Legendary Resistance. If it fails and the monster has a use left (any policy), nothing is ended: the record stays, `monster_concentration.pending` holds the failed save, and a private notice tells the GM. The GM decides with `POST /api/gm/monster-concentration` (`legendary_resistance` spends one use and keeps it; `end` lets the failure stand and removes the spell's conditions). `POST /api/gm/legendary-resistance` also answers a pending decision. Each further damage packet while pending owes its own save: it is QUEUED in `monster_concentration.queue` (the DC, in order) and noted privately. `legendary_resistance` spends one use, then rolls the queued saves in order: a pass keeps going, a failure with a use left makes a new pending decision (the rest stay queued), a failure with none left ends it inside that decision. `end` ends it and drops the queue. The decision is claimed with a conditional UPDATE before the use is spent. Death or Incapacitated ends it at once with no decision. A failed save with no use left ends it at once. A new cast of a Concentration spell clears a pending decision.
- Effect ownership: ending removes only condition records whose source monster is the caster and whose source names that spell. Tested with two casters holding the same-named condition on one character.
- Tested (TestPostgresMonsterConcentrationLifecycle, route level): non-Concentration and unknown-spell casts keep a valid Concentration; both decisions; bad and repeated decisions refused; stored row read back from the table; another campaign's row untouched by a decision; recast and death while pending. Five mutations each fail it (immediate end, ownership ignoring the caster, pending kept on recast, delete without the campaign filter, pending not cleared on Legendary Resistance).
- NOT covered: a cast blocked by Antimagic Field (returns before any start, by code reading only), a cast whose targets are all shielded (the code returns before the start, so no Concentration is recorded even though the spell was cast: a gap, not claimed correct), a server restart (the row is a table, but no restart test), Legendary Resistance policy "always" is not auto-applied to this save (the GM is asked), durations of the spell effects and repeated damage packets (one Constitution save per damage instance is the rule the code follows; multi-packet turns are not separately tested).

Queue tests (same test): two packets while pending give queue "30,30"; Legendary Resistance 1, 2 and 3 walk the queue (pending again, pending again, settled with no use left); a retry is refused and spends nothing; the next failed save with no use left ends it at once; a queued failure with no use left ends it inside the decision; "end" removes the row with its queue; stored pending and queue read back from the table. Mutations that fail it: no queueing, no draining, drain not stopping at a new pending decision. NOT isolated by a mutation: the conditional-UPDATE claim before spending (a sequential retry is already refused by the earlier check); a concurrent double-submit is not tested. Saves are rolled when the GM decides, not when the damage came (the roll is random either way; the order is the damage order).
